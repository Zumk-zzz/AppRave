# Веб-кабинет, Альфа-Банк и Telegram Mini App

Состояние на 15 октября 2026: веб-версия и серверная основа Mini App реализованы.
Эквайринг поддерживает демонстрационный режим и только тестовый шлюз Альфа-Банка.
Боевой приём денег, фискализация и отправка настоящих чеков не подключены.
Сборка остаётся на Expo SDK 54; новых нативных зависимостей нет.

## Веб-версия

`npm run web` запускает браузерную версию. `npm run build:web` создаёт статическую
сборку в `dist`. Адрес сервера задаётся внешней переменной `APPRAVE_API_URL` до
запуска/сборки. Скрипт передаёт в браузер только публичный адрес и источник данных,
никаких банковских паролей или токенов бота. При сборке без адреса на опубликованном
домене используется `/api` того же домена. На localhost — порт 3000.

У администратора на широком экране есть боковое меню. Сессия браузера сохраняется
в пределах вкладки, подтверждения действий работают в браузере, дата вечеринки
редактируется через браузерный календарь. Модальные формы прокручиваются.
На телефоне используются прежние нативные хранилище и календарь.

Для размещения нужен HTTPS-домен и сервер API. Пример reverse proxy ниже нужно
адаптировать к своему хостингу; сертификат и домен здесь не создаются:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3000/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
location / {
    root /srv/apprave/dist;
    try_files $uri $uri.html /index.html;
}
```

Проверяйте прямое открытие и перезагрузку `/admin`, `/payment/<id>` и страницы
билета. Камера в браузере требует подходящего защищённого контекста и разрешения.
Рабочая база и рабочие серверы во время этой доработки остаются остановленными.

## Расчёт и платёж

Клиент отправляет идентификаторы товаров и количество. Сервер берёт цены из БД,
сравнивает с показанной суммой; при изменении цены откатывает резерв и просит
обновить корзину. Суммы хранятся в целых копейках. Email собирается до оплаты и
сохраняется в заказе. Для банковского режима он обязателен.

Платёж получает снимок состава заказа с учётом отменённых единиц. При частичной
отмене до создания платежа сумма пересчитывается. Один заказ → один активный
банковский платёж; после передачи в банк обычные изменения/отмена гостем закрыты,
чтобы ранее выданная платёжная ссылка не оплатила изменённый состав.
При корзине на несколько вечеринок создаются отдельные заказы и отдельные платежи.

По умолчанию `PAYMENT_PROVIDER=stub`: старый демонстрационный сценарий остаётся.
Для тестирования банка заполните только серверный `server/.env`:

```dotenv
PAYMENT_PROVIDER=alfa_test
ALFA_API_BASE=https://alfa.rbsuat.com/payment/rest/
ALFA_USER_NAME=логин_тестового_магазина
ALFA_PASSWORD=пароль_тестового_магазина
PAYMENT_RETURN_BASE_URL=https://ваш-тестовый-домен
ALFA_CALLBACK_URL=https://ваш-тестовый-домен/api/webhooks/alfa
```

Для i-логина тестовый адрес — `https://tws.egopay.ru/api/ab/rest/`. Тип учётной записи
и адрес нужно сверить с выданными банком реквизитами. Используются `register.do`
и `getOrderStatusExtended.do` с банковской формой оплаты. СБП должен быть подключён
банком для этого магазина и включён на его форме; отдельный прямой C2B QR API
в эту реализацию не входит. Без тестового кабинета настоящая связь с банком
ещё не проверена; автоматические проверки используют имитатор транспорта.

Банк присылает callback нам, а не наоборот. Входящий status не считается
доказательством: сервер перечитывает статус через авторизованный API банка,
сверяет номер заказа, сумму и валюту, и только подтверждённое списание переводит
заказ в оплаченный. Холд не является оплатой. Повтор не начисляет баллы дважды;
возврат браузера с банковской страницы не подтверждает платёж.

Оплата после истечения/отмены резерва сохраняется как требующая сверки; новый
вход и товар автоматически не выдаются. Если банк принял регистрацию, а связь
оборвалась до сохранения ответа, повтор не создаёт второй банковский заказ с тем
же номером, но может потребовать ручной сверки в кабинете банка. Автоматическое
восстановление таких попыток и фоновые банковские сверки нужны перед продакшеном.
Банковские возвраты пока явно заблокированы: демонстрационный обработчик не может
выдать фиктивное «деньги возвращены». Четыре существующие защиты возврата сохранены.

## Электронный кассовый чек

Мы можем формировать состав и сумму покупки; этого недостаточно для фискального
чека. Нужна зарегистрированная ККТ: собственная с интеграцией либо облачная.
Покупка отдельного облачного сервиса не является единственным вариантом.
Бумажный принтер в этой доработке не добавляется.

После выбора ККТ подключаются передача состава, фискальные статусы и ссылка на
чек; доставку на email делает касса/ОФД либо настроенный почтовый сервис.
Сейчас email только сохраняется, письма с фискальным чеком не отправляются,
`fiscalReceipt.status=not_configured` показан явно. Банковская квитанция, состав
заказа и самостоятельно созданный PDF не подменяют кассовый чек.

Для билетов, напитков и депозита необходимо согласовать с кассовым интегратором
и бухгалтером предмет/способ расчёта, НДС, систему налогообложения, получение и
зачёт предоплаты, возвраты. Депозитный заказ с нулём новых денег не означает,
что не нужна операция зачёта аванса. Налоговые значения не подставлены наугад;
`orderBundle` для фискализации пока не отправляется.

Источники: [Альфа-Банк: фискализация](https://alfabank.ru/sme/payservice/internet-acquiring/docs/fiscalization-r/),
[ФНС: частые вопросы](https://kkt-online.nalog.ru/faq/),
[официальный REST API Альфа-Банка](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/rest/).

## Telegram Mini App

Та же веб-сборка открывается внутри Telegram. В Mini App появляется кнопка входа
через Telegram. Сервер проверяет HMAC initData, возраст до 10 минут, поля и ID;
имя пользователя и initDataUnsafe не дают прав. Новый аккаунт создаётся гостем.

Если уже есть заказы и аккаунт по телефону/почте, сначала войдите этим способом
внутри Mini App, затем нажмите в профиле «Привязать этот Telegram к моему аккаунту».
После этого Telegram откроет те же заказы. По совпадению имени или username
аккаунты не объединяются, уже занятая привязка отклоняется.

Для включения создайте бота в BotFather, укажите HTTPS-адрес веб-сборки как Main
Mini App/Menu Button и сохраните токен только в `server/.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен_вашего_бота
```

Без токена вход явно недоступен. Бот и публикация здесь ещё не создавались.
Сообщения и рассылки ботом не реализованы. Оплата идёт через ту же банковскую
форму, это не интеграция Telegram Payments/Stars. Работа открытия конкретной
банковской формы из Telegram должна быть проверена на реальных iOS/Android
клиентах после выдачи тестового кабинета. [Документация Mini Apps](https://core.telegram.org/bots/webapps).

## Обновление и проверки

Перед применением миграции сделайте резервную копию рабочей БД. Миграция
`20261015090000_web_payments_telegram` добавляет email чека, уникальный Telegram ID
и учитывает Telegram как самостоятельный способ входа. Затем сгенерируйте Prisma
Client и пересоберите сервер. Рабочая миграция автоматически не выполнялась.

Проверки: типы приложения/сервера, lint, `npm test`, `npx expo-doctor`, сборки web
и iOS. `npm --prefix server run test:payments` проверяет суммы, Telegram и адаптер
без БД. `smoke:web-payments` проверяет сервер с имитатором банка и запускается
только на одноразовой БД с явным `DATABASE_URL` на порту 5546. Общие `smoke:all`
по-прежнему требуют отдельные `API_URL` и `SMOKE_DB_CONTAINER`.
