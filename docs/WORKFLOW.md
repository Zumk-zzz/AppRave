# Работа с AppRave и GitHub

Репозиторий: git@github.com:Zumk-zzz/AppRave.git. Основная ветка: main.
SDK остаётся 54; новые нативные зависимости должны работать в Expo Go.

## Как ставить задачи

Пример: «Добавь отчёт закрытия вечера. Проверь, сохрани коммит и отправь
в отдельную ветку GitHub». Codex работает с файлами открытого проекта;
передавать проект архивом при каждом обновлении не нужно.

Один законченный набор изменений — одна ветка codex/<задача>.
Перед началом проверить git status, текущую ветку и изменения на origin.
Рабочая копия Codex может быть в detached HEAD: сначала создать ветку.
Не переключать основную папку проекта из другого worktree.

## Первый запуск новой копии

Из корня проекта (Node.js 22 или совместимая более новая версия):

```powershell
npm ci
npm --prefix server ci
npm --prefix server run prisma:generate
```

Локальную конфигурацию server/.env создать по server/.env.example,
если файла ещё нет. Секреты не коммитить. Для сервера переменные должны
попасть в окружение процесса; явный запуск из папки server:

```powershell
node --env-file=.env --import tsx src/main.ts
```

База и миграции описаны в RUNBOOK.md. Seed и smoke запускаются только
на тестовой базе: smoke создают и изменяют заказы, товары и сотрудников.
Несколько worktree по умолчанию используют один контейнер apprave-db;
это не изолированные базы. Не запускать smoke на рабочей базе клуба.

## Проверки

```powershell
npm run typecheck
npm test
npx expo-doctor
npm --prefix server run typecheck
npm --prefix server run build
npx expo export --platform ios
```

После новых папок src перезапустить Metro с --clear и проверить бандл
по URL из AGENTS.md. Экспорт проверяет сборку, но не заменяет проверку
камеры, QR и интерфейса на телефоне в Expo Go.

GitHub Actions выполняет проверки приложения и сервера, миграции и
smoke:all в одноразовой PostgreSQL. Для работы не нужны боевые секреты.
Само наличие workflow не запрещает merge: после первого успешного запуска
в настройках GitHub можно сделать mobile и server обязательными для main.

## Отправка изменений

Перед коммитом просмотреть git diff и добавить только файлы задачи.
После проверок:

```powershell
git push -u origin HEAD
```

Доступ по SSH уже настроен на компьютере. Песочница Codex может запросить
разрешение на сетевую команду или запись Git-метаданных; это отдельное
разрешение, не повторная авторизация GitHub.

Pull request можно открыть по ссылке, которую выдаёт git push, или через
интерфейс Codex. GitHub CLI (gh) нужен только для дополнительных операций
с PR и проверками из терминала; обычный git push от него не зависит.
Не передавать токены и приватные SSH-ключи в чат.

Слияние в main выполняется после просмотра изменений и зелёных проверок.
Публикация кода в GitHub не обновляет сервер и приложение у пользователей:
развёртывание — отдельный шаг. При локальной разработке Expo Go получает
изменения от Metro той папки, из которой он запущен.
