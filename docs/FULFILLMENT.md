# Вход компании и очередь бара

## Как пользоваться

У столика администратор задаёт «Проходов включено» отдельно от количества мест.
Например, стол на 6 мест с 4 проходами даёт 4 входа. При значении 0 нужны отдельные
билеты. Условия сохраняются в заказе на момент покупки; правка стола не меняет
уже оплаченные брони. Старые брони автоматически новых проходов не получают.

Компания может показать один основной QR. Фейсер выбирает число людей перед ним
и отмечает, входит ли сейчас владелец заказа. Остальные проходы остаются доступны.
То же количество можно выбрать при ручном проходе из списка гостей.

Для друга, который придёт отдельно, владелец открывает заказ и создаёт личное
приглашение. Оно резервирует один из оставшихся проходов. Друг открывает ссылку,
входит в свой аккаунт и принимает приглашение; получает отдельный QR на один вход.
Друг не получает заказ владельца и не может забирать его напитки. Один человек
может принять ссылку, один раз пройти; владелец может отозвать неиспользованное
приглашение и вернуть проход основному QR. При отмене позиции отзываются все её
неиспользованные приглашения. Отмена вечеринки/возврат тоже прекращают их действие.

В Expo Go ссылка работает, пока телефон друга может подключиться к этому проекту
Metro и API. Для проверки с разных телефонов нужен режим api и доступный обоим
адрес сервера. Автономные моки хранят приглашения только на одном устройстве.

## Напитки

1. Гость оплачивает заказ (сейчас оплата демонстрационная).
2. Фейсер подтверждает вход владельца либо его личный проход по приглашению.
3. Владелец нажимает «Начать готовить» в заказе. Напитки становятся в очередь.
   После отправки в бар гость больше не может отменить эти позиции.
4. Бармен принимает позицию: появляется «Готовится» и имя исполнителя.
   Другой бармен не может одновременно принять ту же позицию.
5. Исполнитель отмечает готовность всего количества или части. Гость видит,
   сколько уже можно забрать и сколько ещё готовится.
6. У стойки гость показывает основной QR. Бармен выдаёт только готовое количество.
   Готовность сама по себе ничего не списывает как выданное.

Очередь и открытый экран заказа обновляются раз в 5 секунд, пока приложение
активно. При потере связи показываются последние данные и ошибка обновления.
Удалённых push-уведомлений в Expo Go нет; готовность нужно смотреть в приложении.

Бармен видит только напитки, фейсер — только проходы. Менеджеру/администратору
доступен общий обзор. В истории фиксируются принятие в работу, готовность,
выдача, сотрудник и смена. Бармен видит свои действия; руководитель — действия
команды. В записи выдачи также видно, кто готовил напиток.

## Обновление установленного сервера

Перед обновлением сделайте обычную резервную копию рабочей БД. Остановите старый
API, подтяните main и из папки server выполните (Node.js 22+; server/.env уже настроен):

```powershell
node --env-file=.env node_modules/prisma/build/index.js migrate deploy
npm run prisma:generate
npm run build
node --env-file=.env dist/src/main.js
```

Затем перезапустите Metro из корня проекта:

```powershell
npx expo start --clear
```

Новая миграция `20261004120000_bar_and_group_entry` добавляет счётчики и приглашения.
Подтверждённые до обновления билетные проходы создают отметку посещения владельца,
чтобы уже вошедшие гости могли отправить напитки в бар. Рабочая база автоматически
при разработке не менялась. SDK остаётся 54, новых нативных зависимостей нет.

## Проверки

`npm test`, `npm run typecheck`, `npm --prefix server run typecheck`, `npx expo-doctor`.
Полный серверный набор: `npm --prefix server run smoke:all`; отдельно новые сценарии:
`npm --prefix server run smoke:fulfillment`.

Smoke запускаются только против одноразовой базы! Задайте `API_URL` тестового API
и `SMOKE_DB_CONTAINER` тестового Docker-контейнера. Сценарии меняют склад, создают
сотрудников, брони и отменяют тестовую вечеринку.
